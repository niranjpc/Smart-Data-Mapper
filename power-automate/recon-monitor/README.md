# Reconciliation Monitor on Power Automate

> **Live in SharePoint without custom script: see [SHAREPOINT-LISTS.md](SHAREPOINT-LISTS.md).** A daily flow fills
> six SharePoint lists and four modern pages show them, with the customer drill-down. That is the route to use
> when the site does not allow custom script. The rest of this file covers the shared Office Script, its
> configuration, and two other delivery options (a page with its own script, an HTML file by e-mail).

Rebuilds the Reconciliation Monitor dashboard automatically. A scheduled cloud flow reads the archived
weekly workbooks and the current Reconciliation Report, applies the dashboard's rules, saves the finished
dashboard as an `.html` file in SharePoint and e-mails a daily summary with the dashboard attached.

```
Recurrence (daily)
  ├─ Get recon-config.json + page template         SharePoint
  ├─ Get files in the archive folder               SharePoint   (one workbook per week, oldest first)
  ├─ For each archived week: Run script (extract)  Excel Online (Business)  → rows of that week
  ├─ Run script ReconMonitor on the current week   Excel Online (Business)  ← all dashboard logic
  │     archiveJson = the weeks above;  returns dataJson · digestJson · subject · emailHtml · tiles · warnings
  ├─ Compose page  = template with dataJson injected
  ├─ Save Reconciliation-Monitor.html + digest     SharePoint (overwrite)
  └─ Send daily summary + attached dashboard       Outlook
```

The rules live in one Office Script because a flow cannot loop over ~50,000 customer × interface × day
cells in reasonable time; the script does it in well under a second and is called with a single action.

**No custom script needed.** The flow does not put a script page into SharePoint to be run there. The
saved `.html` and the e-mail attachment open in the browser like any downloaded file, with all dashboards
and the customer drill-down working.

There are two ways to run it; both use the same rules code and the same configuration file.

| | Live page in SharePoint | Power Automate flow |
|---|---|---|
| How | `sharepoint/Reconciliation-Monitor.aspx` reads the tracker workbook each time it is opened | A daily flow runs the Office Script and saves / e-mails the dashboard |
| Freshness | Always the last saved tracker | As of the last flow run |
| Needs | Site with **custom script allowed** (admin) | Flow + Office Script; no admin setting |
| Extras | `?asOf=yyyy-MM-dd`, `?mode=inspect` | E-mail summary with the dashboard attached, digest JSON |

| File | Purpose |
|---|---|
| `sharepoint/Reconciliation-Monitor.aspx` | Self-contained live page for SharePoint (generated by `sharepoint/build.mjs`) |
| `sharepoint/src/` | Workbook reader and loader used by the live page |
| `office-scripts/ReconMonitor.ts` | The logic: read tracker, align names, classify feeds, KPIs, highlights, anomalies, history, e-mail body |
| `dashboard/recon-monitor.template.html` | The dashboard page without data (`"__RECON_DATA__"` placeholder) |
| `config/recon-config.sample.json` | Settings: sheet/column mapping, customer name alignment, thresholds |

## What the script decides

Each **feed** is one customer × interface × day.

| Rule | Definition |
|---|---|
| In scope | The schedule tab marks the interface type as running on that weekday for the customer |
| Fully reconciled | A tracker row exists and \|variance\| ≤ 0.5 (not counted when the schedule explicitly says "not scheduled") |
| Not fully reconciled | A tracker row exists and \|variance\| > 0.5 — split into tracked / not tracked via ticket |
| Scheduled but not reported | In scope, no tracker row, and no row with an explanatory comment (N/A, no run, no file, holiday, on hold) |
| Reconciled rate | fully reconciled ÷ (fully + not fully reconciled), rounded |
| Σ\|variance\| | Sum of absolute variances of the not-fully-reconciled feeds |
| Volume anomaly | Received > 3× or < ⅓ of the median of the previous ≤ 20 reported days (last 45 days, ≥ 6 days of history, median ≥ 200); the latest day is only checked for spikes |
| Name alignment | Tracker names are mapped through `accountAliases`; names that map to the same customer are merged (counts and \|variance\| summed, ticket kept if any row has one) |
| Schedule type | `Provider IB – *` interfaces follow the `Provider IB` schedule, `Encounter Rejections` follows `Encounter Submission` |
| Default day | Latest day with at least 60% of the busiest day's rows (or `minRowsForDefaultDay`), so a half-filled "today" does not become the headline |
| Highlights | Day: biggest variance, variances needing a ticket, feeds not reported, volume check, vs previous day. Week: top contributor, feeds failing 2+ days, worst day, vs previous week. Month: vs previous month, heaviest week, most days not reconciled, ticket coverage |
| History | Weekly reconciled rate per customer with last-4 vs prior-4 weeks, recurring issues (weeks affected, longest run, % ticketed), weekly quality (rate, ticket coverage, schedule adherence) |

## How to check it

**1. On your PC (no SharePoint set-up needed).** Open `sharepoint/Reconciliation-Monitor.html` in Edge or
Chrome, pick the current workbook, the archived weekly workbooks and `recon-config.json` together. The files
are read in the browser, nothing is uploaded. This is the same page and code as the SharePoint version.
Add `?mode=inspect` to the address to see which sheets and columns were matched, `?asOf=2026-11-09` to
view an earlier day.

**2. In SharePoint.** Follow the steps below, then open `…/Reconciliation-Monitor.aspx?mode=inspect` first
and the page without parameters after. If the page downloads instead of opening, or the upload of the
`.aspx` is refused, custom script is disabled on the site (see the note under the steps).


The page holds everything: the rules, a built-in `.xlsx` reader and the dashboard. On opening it fetches
`recon-config.json` from its own folder, downloads the tracker through the SharePoint REST API with the
viewer's sign-in, computes the dashboard in the browser and renders it. No data is stored in the page.

1. Upload `sharepoint/Reconciliation-Monitor.aspx` and your `recon-config.json` to one folder of a
   document library (for example `SiteAssets/ReconMonitor`).
2. In `recon-config.json` set `siteUrl` (site that holds the report), `trackerPath` (server-relative path
   of the current workbook), `archiveFolder` (folder with the archived weekly workbooks, optional) and
   `timeZone` (IANA name, used for "today").
3. Open `…/Reconciliation-Monitor.aspx?mode=inspect` — it lists the sheets and the columns matched per
   interface. Adjust the configuration (see the table under *Match the configuration to the tracker*).
4. Open the page without parameters, then link or embed it the same way as the Batch Monitor page.

- Viewers need read access to the tracker workbook; the page shows what the last **saved** version contains.
- **Custom script.** A page with its own script only runs on a site where custom script is allowed
  (*Allow users to run custom script*; PowerShell `Set-SPOSite <site> -DenyAddAndCustomizePages 0`). It is
  off by default on modern sites and only a SharePoint admin can change it; Microsoft has also made the
  setting revert automatically after a period unless the tenant delays that. Ask your admin which applies.
  If it cannot be allowed, the same code can be packaged as an SPFx web part, which runs without it.
- `?asOf=2026-11-06` shows the dashboard as of an earlier day; `?config=<url>` uses another configuration file.
- Tracker warnings (unmatched sheets, columns, account names) appear in a collapsible note at the bottom.
- Setting `dataUrl` in the configuration makes the page load a published dataset (the flow's `dataJson`)
  instead of reading the workbook.
- After changing `office-scripts/ReconMonitor.ts` or the template, run `node sharepoint/build.mjs` and
  upload the page again.

## Power Automate flow

### 1. Files in SharePoint

Create a folder for the monitor (for example `Shared Documents/Recon/Monitor`) and upload

- `dashboard/recon-monitor.template.html`
- `recon-config.json` — a copy of `config/recon-config.sample.json` with your values
  (`siteUrl`, `trackerPath`, `archiveFolder` and `timeZone` are only used by the live page and can stay as they are)

The flow saves `Reconciliation-Monitor.html` and `recon-digest.json` into the same folder.

### 2. Office Script

Open the current Reconciliation Report in Excel for the web → **Automate → New script**, paste
`office-scripts/ReconMonitor.ts`, rename the script **ReconMonitor**, save. The script is stored in your
OneDrive and can be run by the flow on any workbook, including the archived weeks.

Check it once from Excel: run it with `mode` = `inspect` and paste the contents of `recon-config.json` into
`configJson`; the `warnings` output lists, per interface, the sheet, header row and columns matched.

### 3. Match the configuration to the tracker

The built-in defaults match the Reconciliation Report workbook, so the configuration normally only needs
the customer name mapping and the paths. How the workbook is read:

- **Tables** — one sheet per interface; a table starts at the header row (the row with a `Variance` column).
  `Provider IB` holds five stacked tables (Tax entity, Practitioner, Supplier, Supplier Location, Practitioner
  Role) and `Encounter Submission` two (extraction, rejections); each is picked by the title above its header.
- **Rows without a date are ignored** (pre-filled template rows). Dates are never filled down.
- **A dated row with no counts entered is not a report**: the feed shows as *scheduled but not reported*,
  unless the File Name / Comments text explains it (N/A, no file, no load, no run, holiday, on hold, out of scope).
- Several rows for the same customer, interface and day (files, lines of business) are added up.
- **Variance** is the value in the Variance column. If that cell is empty, it is calculated from the formula in
  the header (`A-(B+C+D+E)`) using the lettered columns; totals defined in a header (`E = F+G+H+L+M+I`) are
  derived the same way when blank.
- **Tracked via ticket** = either Jira Ticket Number column is filled in.
- Customer names ignore case, spacing and punctuation (`PlanOne` = `Planone`, `Plan Two` = `PlanTwo`).
- **Schedule** — tab `Recon Report Schedule`: Account (merged cells), Report Type, an `X` per weekday. The
  `Monthly` column and `TM Aging Summary` rows are not used.
- Received / loaded / error / pending shown per interface come from: Received, Triggered, sent to print vendor,
  eligible claims, payments inserted, sent to external vendor → *received*; Loaded into HRP, Extracted, status
  received, submitted by clearing house, acknowledgement received, total payment sent → *loaded*; EDIFECS /
  I-Plus errors, rejected by client, failed count, EDI rejections → *error*; Workbasket and pending columns → *pending*.

Run with `mode` = `inspect` (or open the SharePoint page with `?mode=inspect`) to see, per interface, the
sheet, header row and columns matched, and adjust `recon-config.json` if a sheet differs.

| Setting | Meaning |
|---|---|
| `startDate` | First day of the archive (snapped back to a Monday) |
| `siteUrl`, `trackerPath`, `timeZone` | Live page: site and server-relative path of the current workbook; IANA time zone for "today" |
| `archiveFolder`, `archivePattern` | Live page: folder with the archived weekly workbooks (every `.xlsx` in it is read, optionally filtered by a file-name pattern) so the history spans all weeks |
| `interfaces[]` | Omit to use the built-in report layout. Otherwise `name` (as shown on the dashboard), optional `sheet` (default = name), `block` (title above the table when a sheet holds several), `scheduleType`, `columns` overrides, `variance` (formula to use when the Variance cell is empty, e.g. `A-(B+C)`), `filterColumn` / `filterEquals` |
| `columns` | Header patterns per role (`date`, `account`, `received`, `loaded`, `error`, `pending`, `variance`, `ticket`, `comment`). Case-insensitive regular expressions. Count roles add up every matching column, e.g. Claims IB received = `paper` + `edi` |
| `accountAliases` | Tracker name → dashboard name. Several tracker names may share one dashboard name |
| `ignoreAccounts` | Tracker names to leave out |
| `unmappedAccounts` | `keep` (default: show under the tracker name, with a warning) or `drop` |
| `scheduleSheet`, `scheduleIgnoreTypes` | Schedule tab and report types on it that are not interfaces. Other layouts also work: Account + one column per interface type; or Account, Interface, Schedule (`Daily`, `Mon-Fri`, `Tue, Thu`, `N/A`) |
| `explainedCommentPattern` | Comment text that explains a missing feed |
| `varianceWhenMissing` | `formula` (default: use the header formula when the Variance cell is empty) or `none` |
| `dateOrder` | `MDY` or `DMY` for dates stored as text |
| `minRowsForDefaultDay`, `anomalyMinMedian`, `anomalyFactor` | Thresholds described above |
| `homeUrl`, `dashboardUrl` | "TechOps home" button on the page; link in the e-mail |

### 4. Build the flow

Create a **Scheduled cloud flow** and add the steps below (this is the HTML-file variant; the SharePoint-lists
flow in `flow/daily-refresh.json` shares steps 1–8a, see SHAREPOINT-LISTS.md). Name the steps exactly as in the first column so
the expressions work as written.

| # | Step name | Action | Settings |
|---|---|---|---|
| 1 | — | **Recurrence** | Daily, your time zone, after the report is normally filled in (e.g. 07:15) |
| 2 | `Settings` | **Compose** | The object shown below |
| 3 | `Get_config` | SharePoint · **Get file content using path** | Site = your site, File path = `outputs('Settings')?['configPath']`, *Infer content type* = **No** |
| 4 | `Get_template` | SharePoint · **Get file content using path** | File path = `outputs('Settings')?['templatePath']`, *Infer content type* = **No** |
| 5 | `Get_archived_weeks` | SharePoint · **Get files (properties only)** | Library = the library holding the archive, *Limit entries to folder* = the archive folder, *Order By* = `Modified asc`, *Filter Query* = `FSObjType eq 0` |
| 6 | `Only_workbooks` | **Filter array** | From = `body('Get_archived_weeks')?['value']`; advanced mode: `@and(or(endsWith(toLower(item()?['{FilenameWithExtension}']), '.xlsx'), endsWith(toLower(item()?['{FilenameWithExtension}']), '.xlsm')), not(startsWith(item()?['{FilenameWithExtension}'], '~')))` |
| 7 | `Initialize_archive` | **Initialize variable** | Name `archive`, Type **Array**, Value `[]` |
| 8 | `For_each_archived_week` | **Apply to each** over `body('Only_workbooks')` | Settings → *Concurrency control* **On**, degree **1** (keeps the weeks in order) |
| 8a | `Run_script_on_archived_week` | Excel Online (Business) · **Run script** (inside the loop) | Location = your site, Library = archive library, File = `items('For_each_archived_week')?['{Identifier}']`, Script = `ReconMonitor`, `configJson` = `base64ToString(body('Get_config')?['$content'])`, `asOf` = `convertTimeZone(utcNow(), 'UTC', outputs('Settings')?['timeZone'], 'yyyy-MM-dd')`, `mode` = `extract`, `archiveJson` empty |
| 8b | `Add_week` | **Append to array variable** (inside the loop) | Name `archive`, Value = `body('Run_script_on_archived_week')?['result']?['extractJson']` |
| 9 | `Run_script` | Excel Online (Business) · **Run script** | File = the current Reconciliation Report, Script = `ReconMonitor`, `configJson` and `asOf` as in 8a, `mode` = `build`, `archiveJson` = `concat('[', join(variables('archive'), ','), ']')` |
| 10 | `If_nothing_was_read` | **Condition** `body('Run_script')?['result']?['ok']` is equal to `false` | Yes branch: **Terminate**, status Failed, message `join(body('Run_script')?['result']?['warnings'], ' | ')` — keeps yesterday's dashboard when nothing could be read |
| 11 | `Compose_page` | **Compose** | `replace(base64ToString(body('Get_template')?['$content']), '"__RECON_DATA__"', body('Run_script')?['result']?['dataJson'])` |
| 12 | `Save_page` | SharePoint · **Send an HTTP request to SharePoint** | Method POST, Uri `_api/web/GetFolderByServerRelativeUrl('@{outputs('Settings')?['outputFolder']}')/Files/add(url='@{outputs('Settings')?['pageFile']}',overwrite=true)`, Body = output of `Compose_page` |
| 13 | `Save_digest` | Same action | `url='@{outputs('Settings')?['digestFile']}'`, Body = `body('Run_script')?['result']?['digestJson']` (optional) |
| 14 | `Send_daily_digest` | Office 365 Outlook · **Send an email (V2)** | To = `outputs('Settings')?['mailTo']`, Subject = `body('Run_script')?['result']?['subject']`, Body (code view `</>`) = `body('Run_script')?['result']?['emailHtml']`, Importance = `if(body('Run_script')?['result']?['needsAttention'], 'High', 'Normal')`, **Attachments**: Name = `Reconciliation-Monitor.html`, Content = `outputs('Compose_page')` |

`Settings` (step 2):

```json
{
  "siteUrl": "https://TENANT.sharepoint.com/sites/TechOps",
  "configPath": "/Shared Documents/Recon/Monitor/recon-config.json",
  "templatePath": "/Shared Documents/Recon/Monitor/recon-monitor.template.html",
  "archiveFolder": "/Shared Documents/Recon/Archive",
  "outputFolder": "/sites/TechOps/Shared Documents/Recon/Monitor",
  "pageFile": "Reconciliation-Monitor.html",
  "digestFile": "recon-digest.json",
  "timeZone": "Eastern Standard Time",
  "mailTo": "techops-recon@TENANT.com"
}
```

`configPath` / `templatePath` are relative to the site, `outputFolder` is server-relative (starts with
`/sites/...`), `timeZone` is a Windows time-zone name as used by `convertTimeZone`.

**Check on the first run**

- **Archive file reference (step 8a).** The file is passed as `{Identifier}` from step 5. If the Excel action
  reports that the file cannot be found, use its path inside the library instead, e.g.
  `concat('/Recon/Archive/', items('For_each_archived_week')?['{FilenameWithExtension}'])`.
- **Order of weeks.** Weeks are taken oldest first by *Modified*. If an archived file is edited later, it is
  read later; that only matters when two workbooks hold the same day (then the later one wins).
- **Run script limits.** Each call may run 120 s; there is a daily limit on the number of calls per user
  (1,600 at the time of writing) — one call per archived week plus one, per run.
- **Size.** Each archived week adds about 20 KB to `archiveJson`; the finished page is about 0.4 MB for
  19 weeks. If the archive grows large, keep only the weeks you want in the history in the archive folder
  (or filter step 6 on `Modified`).

**Where people open it**

- The e-mail attachment `Reconciliation-Monitor.html`: open it, and the whole dashboard runs in the browser.
- The saved file in the SharePoint folder: SharePoint downloads it (it does not run pages with script), then
  it opens in the browser. Link the Batch Monitor page to this file.
- For Teams, add *Post message in a chat or channel* with `result/subject` and a link to the file.

### Script outputs available to the flow

`ok`, `asOf`, `defaultDay`, `generated`, `dataJson`, `digestJson`, `subject`, `emailHtml`, `extractJson` (mode `extract` only),
`needsAttention` (variances without a ticket or feeds not reported on the default day), `warnings[]`,
`dailyLabel` / `weeklyLabel` / `monthlyLabel`, and for each of `daily`, `weekly`, `monthly`:
`inScope`, `fullyReconciled`, `notFullyReconciled`, `trackedViaTicket`, `notTrackedViaTicket`,
`notReported`, `varianceSum`, `reconciledRate` (−1 when no feed was reported).

`digestJson` adds, per period: highlights, customers at a glance, interface summary, top variances,
not-reported list and volume anomalies; plus the `history` block.

## Tests

```bash
node tests/run-tests.mjs                                   # synthetic data
node tests/parity.mjs "<existing Reconciliation-Monitor.html>"   # compare with a hand-built dashboard
node tests/sharepoint-lists.mjs "<existing Reconciliation-Monitor.html>"   # SharePoint lists: setup + 2 daily runs on a strict mock SharePoint, rows vs original
tsc --noEmit --strict --target ES2019 --lib ES2019 office-scripts/ReconMonitor.ts tests/excelscript.d.ts
```

`parity.mjs` rebuilds a tracker from the data embedded in an existing dashboard file, runs the script on
it, and compares every period (each day, week and month, portfolio and per customer) with the numbers,
lists and highlight sentences the original page computes — both for the script's own engine and for
the template rendered with the script's data.

## Notes

- Run script limits (at the time of writing): 120 s per call, a few MB of input/output, 1,600 calls per
  user per day. With ≈ 19 weeks the page is ≈ 0.4 MB and `archiveJson` ≈ 0.36 MB.
- The page template differs from the hand-built page in four places: data comes from the placeholder,
  the name-alignment block is gone (the script does it), the preview banner became a "refreshed" stamp,
  and the per-feed key now allows archives longer than 400 days.
- The built-in workbook reader handles standard `.xlsx` / `.xlsm` files; it does not read `.xlsb`, `.xls` or password-protected workbooks.
- The schedule tab of the current workbook is applied to every week of the archive, as on the original dashboard.
- The flow reads the archived weeks with one `extract` call each and passes them to the run on the current week; the live page reads the archive folder directly. Both give the same dashboard.
- `Claims Payment Extract` has no Variance column, so its reported rows count as reconciled.
